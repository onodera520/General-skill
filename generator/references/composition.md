# 构图：可读地组织已确定的空间

输入为叙事目的、机位、人物 Blocking 和场景档案。填写 [Shot Spec](../templates/shot-schema.json) 的 composition 及 storyboard_keyframe.composition。

## 构图契约

foreground、midground、background 明确列出实体／地标及可见部分；没有该层主体时用空数组，不为了三层齐全添加无关人群或道具。focus_order 给出观众读取次序；visual_center、negative_space、occlusion 和 design_reason 解释视觉组织如何服务本镜信息。

人物调度决定人在何处，构图决定这些人与环境的可见关系；两者不分别改位置。构图改变必须回到机位／Blocking 协调，保留同一世界布局和状态。

## 选择规则

- 空间建立镜头让相关人物、出入口、障碍及目标同时可辨；可用地标作为尺度线索。
- 交接镜头优先让物件和参与手清楚，利用背景明暗或留白分离轮廓，不靠擅加聚光灯或更换道具颜色。
- 对话越肩明确前景肩部属于谁、遮挡比例和倾听者／说话者位置，不能让前景人遮住关键动作。
- 移动镜头在方向前方留路径空间，视线镜头为视线目标留可读空间；不给每种情境强制同一比例。
- 中心、三角、对称、引导线只在服务叙事时使用，不为构图漂亮挪动固定门窗或改变剧情站位。

顶层 composition 表示 t=0 画面；关键帧另按具体时间确定。静态 Image Prompt 只用关键帧构图；Video Prompt 说明已经在 Spec 规划的构图变化。若无法同时看到所有关键动作，调整机位／景别或返回拆镜，不能把不可能的多视角强行放进一帧。
