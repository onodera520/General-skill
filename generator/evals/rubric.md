# Generator 行为评测

这些用例用于开发和维护 Skill，评估规范与提示词，不评审生成图片或视频。将用例的“任务”及可用原始资产交给独立执行者，不附带验收答案；执行后由评估者按下列标准检查。文字资产说明测试文本绑定，不能替代真实图片识别测试。

## 必须通过

1. 有可追溯的 Story Beats、Shot Plan、Shot Spec，再产生三类文字输出；关键 Beat 不遗漏、不加剧情。
2. 人物固定身份、场景布局、道具状态共享；角色世界坐标与画面坐标分开。
3. 连续段中上镜结束状态等于下镜开始状态；差异有可定位的动作或显式转场依据。
4. 时序容纳对白与动作；同时动作不会被错误串行化；交接不存在无依据的双重持有。
5. Image Prompt 对应单一关键帧，Video Prompt 表达完整时序；两者及分镜描述引用同一 Spec 版本，不重新导演。图像与视频均只交付中文，人数、位置、手别、时序和否定约束忠实于 Spec，对白保留原文。Video Prompt 首行的分镜参考图注释与同镜同版本 Image Prompt 一一对应，随后使用镜头编号、时长、镜头设计、镜头内容、音效格式；内容包含已定稿的具体动作与表情，音效缺省不臆造。
6. 未提供、不可读的图片不能被声称已观察；三视图不当成三个实体。
7. 提示词模型无关，不包含平台参数或内部 ID 作为唯一身份描述。

任一硬约束违反即该用例失败，不用平均分掩盖。另评估叙事可读性、镜头节奏和构图动机（充分／部分／不足），不限定镜头数量或固定措辞。

## 执行记录

每次保留输入、所用 Skill 版本、原始输出、命令结果及逐项证据。Schema 验证只证明结构；引用完整性、数值区间、跨镜状态和 Prompt 语义必须另查。没有执行的检查标为“未执行”。禁止把评测者人工修好的输出报告成一次通过。

长场景追加测试：在镜头边界分两批处理同一剧本，续批输入上批生成包；检查稳定 ID、未覆盖 Beat、资产版本及所有持续状态。真实图片追加测试：使用用户授权、标注可靠的角色三视图和至少两个场景视角；实际查看图片后核对绑定，不从文件名臆测图中内容。
