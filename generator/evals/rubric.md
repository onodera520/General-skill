# Generator 行为评测

仅维护Skill时使用，评估设计与提示词，不审查实际图片／视频。给独立执行者原始任务与必要输入，不给验收答案或旧输出。实际观察生成的Markdown和必要的开发工作记录；正文关键词或Schema通过不能证明语义正确。

## 必须通过

1. 内部顺序为Beats与资产 → 最小补全 → 最短可理解时间线定稿 → Clip分组 → Shot设计 → 只读转写，不为凑片长反向改变估时。
2. 默认交付一个UTF-8 Markdown文件，每个Clip仅有详细镜头描述、逐Shot Image Prompts、一份整体智能镜头 Prompt；对话给真实文件链接。明确请求结构化导出才使用2.0包。
3. 剧情、原台词不删改；顺序／并行和部分重叠正确计时；补充可视化不增加时间；必要动作可执行，无非剧情留白。
4. 优先10–15秒，不主动拆可合并内容；自然短段、尾段、超长紧密因果例外有依据。单个微动作不独立包装，普通因果关系不锁成整场超长Clip。
5. 每段台词／原有旁白在音轨上只记录一次；超过5秒台词有语义相关切镜，V.O.保留说话者与原音连续，不重播、不改语种、不新增叙述旁白。
6. Clip首尾事件不重复，物理入口／出口状态、人物手别、道具数量和运动节奏连续；同场景续接以单人中景／近景／特写或空镜开场。静态站位列出仍在场的全部人物，画外不强行入画；换场和闪回用各自空间状态。
7. 角色世界位置与画面位置分开。每个可见人物在Image Prompt明确相对于镜头的朝向，头脸与视线不混淆；禁止直视镜头与互动人物全部面向镜头。
8. 清晰角色资产只声明严格继承对应图，不重复固定形象；冲突以资产为准。不可用图片不假称已观察，三视图是同一实体；动态脱衣／湿污仍继承事件。
9. NPC只在原文明确存在群体时补全差异化身份标签与动作，不从街道／店铺名称自动新增群体。抽象可视化按微动作、神态、道具、环境、隐喻次序，后者不新增剧情。
10. 逐Shot图号与Clip Video引用的Shot版本、关键帧时间／用途准确；代表帧不当视频首帧。Clip局部时间覆盖全部画面，声音原文只出现在声音部分；台词{}、音效<>，新描述用具体名字，原台词代词不改。
11. Prompt Builder不重新选镜头、时长、NPC、动作或声音。某Shot的局部限制不扩成全Clip；全局补充确实贯穿该Clip。中文、模型无关，不添加专属参数。

任一硬约束违反即用例失败。可读性与节奏另评充分／部分／不足。附加结构化用例检查7个Schema、Clip／Shot／声音引用、版本、源文字区间、场景入口与覆盖；自动验证只证明可机械判断的部分。

## 执行记录

保存原始输入、实际输出、Skill版本和检查结果。没执行的检查注明未执行，不能把人工修好的产物报告为独立一次通过。真实图片识别另需真实可查看资产；文字绑定和已核实绑定记录仅能测试转写逻辑。

使用 [Clip用例](clip-pipeline.md)、[Spec保真](spec-prompt-fidelity.md) 以及基础、对话、动作、资产歧义用例。分批追加验证全局Clip／Shot／图号、ID、版本和持续状态；旧1.x输入验证重新分组与重写视频，不直接拼接旧Prompt。
