# 资产缺失、三视图与版本

## 任务

剧本：阿青穿湿外套走入厨房，把缺口白杯放在东侧水槽，脱下外套挂到门边，穿绿衬衫走出厨房；十分钟后回来，拿起原来的杯子。附件清单声明但未实际提供：一张名为 aqing-three-view.png 的三视图、一张厨房图、一个打不开的杯子路径。文字资产说明：三视图为同一角色正侧背，短黑发、灰外套、绿衬衫；厨房北门、东侧水槽、门边挂钩固定。不向用户逐镜提问，输出完整草案。不要声称实际见过附件。

## 验收

- 声明图片不可用，文字说明标为用户提供；不臆造正侧背细节或缺口精确朝向。
- 阿青只有一个实体；三视图不会生成三个人或三栏拼图。
- 杯子缺口、灰外套湿态、挂钩位置持续；脱衣后绿衬衫可见，有状态事件。
- 十分钟是显式时间省略，不擅自假定杯子被别人移动或外套完全变干。
- 追加一张用户指定替换旧版的角色资产时，仅升级该实体版本；重新生成受影响镜头及 Prompt，不混用旧版本。

## 定向用例：清晰角色资产继承

使用实际可查看的清晰角色资产，或仅为转写评测提供已经核实的绑定记录；后者不能声称本次重新观察了图片。

1. 两角色清晰绑定角色参考图A与B，Spec 内部已记录发型和服装。三项正文应逐人声明严格继承其角色参考图，不重复发型、脸型、服装颜色／款式清单；仍写每个可见人物的相机相对朝向、表情、动作、遮挡及交接手别，不把人物标签与“分镜参考图：图N”混淆。
2. 图片可见黑发灰外套，而文字称金发红外套：设计阶段按图片纠正固定形象，不能折中；只读旧 Spec 转写发现该冲突时返回绑定／设计阶段，不能照抄冲突文字或暗改 Spec。核对 must_have 与负面文字也未重新引入冲突形象。
3. 剧本明确脱下资产中的外套并挂在门边，或外套逐渐淋湿：保留资产继承与该动态变化，记录状态承接，不能因“严格继承”恢复穿着或干燥状态；不凭空设计不可见内搭。
4. 仅提供文字设定或图片不可读、身份有歧义：沿用已确认文字／标明缺失，不输出已清晰匹配的假声明。当前人物被局部遮挡但其资产先前清晰绑定时仍继承原资产，不重新定义形象。
5. 用户替换适用资产后，同步绑定与 Spec 版本，三项正文沿用新引用；下游 Prompt 不再残留旧形象描述。最终交付仍只有逐镜详细描述、Image Prompt、Video Prompt。
