# Spec 转写保真

## 任务

提供一份定稿镜头设计：SHOT_003，spec_version=2，4 秒中景、平视、固定机位。短黑发深蓝夹克的林川在画面右侧前景，面向左侧的长黑发绿衬衫阿岚；关键帧中林川身体相对镜头呈四分之三背面，阿岚身体相对镜头呈四分之三正面。0–1 秒双方静止；1–2 秒林川右手把红钥匙交给阿岚左手；2–4 秒阿岚握住钥匙，林川右手已空。东侧桌上方固定白吊灯照亮两人，米色外套留在桌上。Image Prompt 的关键帧在 0.5 秒，为起始静止阶段的代表帧；必须看见钥匙仍在林川右手。整个镜头禁止添加第三人、重复钥匙或运镜。只转写中文分镜描述、中文 Image Prompt 和中文 Video Prompt，不重新导演。引用源文片段保留追溯，不编造原输入没有的 JSON 路径，不改变事实。

## 验收

- 本只读单Shot用例机械封装为单Clip；图像与描述引用Shot版本，视频引用Clip及来源Shot版本。Image Prompt 是交接前：阿岚尚未持钥匙；Video Prompt 则包括交接全过程。
- 中景、平视、固定机位、两人位置、手别、吊灯和桌上外套不改变。
- 不为“电影感”新增特写、推进、烟雾、暖色逆光或背景人物。
- 若输入 Spec 另有“钥匙在阿岚右手”的相冲突字段，Prompt Builder 返回设计阶段修订，不暗自择一。
- 为本用例另造错误输出（反转左右、复制钥匙、增加推进、使用专属参数），确认评测能识别这些语义变化。


## 定向用例：逐人相机相对朝向

仅测试关键帧调度与中文 Image Prompt 转写，这些仅Image转写用例不要求生成Clip视频。将各项“输入”分别交给执行者，再用“验收”检查实际输出，不能只用关键词数量判定。

1. **双人正反打。** 输入：甲黑短发蓝夹克、乙长黑发绿衬衫；两人世界位置和身体朝向不变。第一镜关键帧甲为四分之三背面、乙为四分之三正面；反打关键帧甲为四分之三正面、乙为四分之三背面。分别输出中文 Image Prompt。验收：两份文字逐人写明对应镜头关系，不把上一镜朝向复制到反打，不改变世界站位。
2. **背身回头。** 输入：单个角色灰外套，身体背向镜头，头转向自身左侧，使头脸相对镜头呈四分之三侧后关系，视线看画外门口。验收：中文须保留身体背面、头部转向和视线区别；不能写成整个角色正面或直视镜头。
3. **多人、背景与遮挡。** 输入：甲在前景侧身对镜头；乙在中景四分之三背向镜头、下半身被桌遮挡；丙在背景正面朝镜头但看画外；丁完全画外，戊完全在实墙后不可见。验收：甲乙丙各有明确关系；不漏背景丙、不把乙补成全身、不把正面朝向等同看镜头，不把丁戊加入画面。
4. **运动中途关键帧。** 输入：人物原地身体朝北，摄像机起始在人物正南向北；关键帧时到人物正东向西，平视，无人物转身。调度阶段先写关键帧 facing，再转写中文。验收：世界朝向仍北，关键帧是侧面而非起始背面；该人物自身右侧朝向镜头，朝向在定稿前确定，Prompt Builder不重新设计。
5. **只读缺项负例。** 输入：定稿仅写“甲站右边，朝西，看着乙；乙站左边，朝东看甲”，未给相对镜头朝向或可定位机位。验收：不能把这些句子当成已满足要求；返回设计阶段补齐，不自行将两人统一为正面。
6. **错误候选判定。** 候选包括：遗漏背景人物朝向；Spec 为背面、Prompt 写成正面；把“侧身”改成“直视镜头”；中途帧沿用起始背面。验收：每项指出具体受影响人物／字段和关系错误，不仅检查是否含有“镜头”一词。

Shot Schema兼容性：关键帧facing仅以description说明相机相对朝向，字段、类型和必填结构不变。结构验证通过不能证明上述语义通过。静态关系缺失的旧示例仍可符合Schema，但不能冒充满足新Image Prompt要求。

## 定向用例：中文视频格式与可见表现

1. 定稿 SHOT_001 v1：2秒近景，全程固定，正面平视便当柜玻璃门与标签；柜内一份便当、小价签、冷白灯照亮塑料盒边缘、玻璃映出冬日傍晚窗外，0–2秒冷柜嗡鸣，无人入画不开柜门。只转写 Video Prompt。验收：智能镜头模板的镜号、单镜时长与画面完整，分镜参考图注释匹配本Shot，声音进入【音效】尖括号；原有画面细节与数量保留，不生成英文。
2. 定稿 SHOT_002 v1：4秒中景平视固定；灰外套人物站在门边，右手始终握手机。0–1秒肩膀下垂，1–2秒抬眼望画外门口并张口又闭上，2–4秒保持原地；动作意在表达无助。未指定音效。验收：具体表现、时间和持物完整；不添加跪地、双手抱头、哭声；音效为“未指定”。另提供只有“无助”而无具体表现的只读 Spec，执行者应返回设计阶段，不自行编造表演。
3. 转写本文件开头交钥匙用例，追加1–2秒林川说“接住”，明确无音效。验收：对白原文仅在首次连续台词条目，交接左右手与时间不变，音效“无音效”不删除对白。将明确无音效改为未提供时，应区别对待。
4. 输入0–2秒固定、2–4秒缓慢向右横移的运镜，代表帧为3秒，完整动作起点为0秒。验收：镜头设计保留分段秒数与路径，镜头内容从真实0秒开始，不以代表帧起态截断镜头。
5. 完整生成包为2.0：shots[].image_prompt.zh_cn与clips[].video_prompt.zh_cn；prompt_languages为["zh-CN"]，输入契约仍1.1，Shot仍1.0。验收：通过结构验证；不保留英文必填项、英文空壳或分镜稿英文章节；人物朝向定向用例仍满足。

6. 分镜图一一对应：全局镜头7（SHOT_A v2，Image Prompt 代表帧1.5秒）与镜头8（SHOT_B v3，Image Prompt 起始帧0秒）分别已有图7、图8的逻辑图号，但尚无生成图片。验收：智能镜头 Prompt 在每个镜头段前引用对应图号和正确关键帧；不重置为图1、不虚构文件路径、不把1.5秒代表帧当首帧。将镜头7错配图8或旧版v1 Image Prompt时应识别并纠正对应后交付，不能仅匹配显示序号。只读输入缺少配套 Image Prompt时标待提供，不声称已配对。

## 定向用例：精简交付

任务：使用本文件开头的定稿镜头，按默认方式交付；随后再交付同场另一镜。不得额外要求用户提供 JSON。验收：实际生成一份可读取的 UTF-8 .md 文件，对话提供指向该文件的链接而非重复贴全文；用户指定文件名时遵从，未指定时使用 storyboard.md 或不重名名称。文件中各Clip依次只有“详细镜头描述、逐Shot Image Prompts、一份整体智能镜头 Prompt”三项，中文，图号与视频逐镜参考图一一对应；没有项目概览、字段表、内部数据包或英文版本。动作交接、左右手、静态关键帧和连续性不能因格式精简而遗漏。检查工作记录确认仍以定稿 Spec 为源，不能从未展示中间文档推断跳过设计。多个Shot按已有定稿区间组织Clip，不将每个Shot自动等同一个Clip。此用例检查默认交付；其他明确要求完整生成包的用例继续检查可选结构化导出。

智能镜头格式兼容：只读4秒定稿输入不擅拆Shot或改变时长；正文用先后动作描述完整交接，不输出原起止秒数区间，原时间约束仍在内部保留。完整生成入口才默认优先0.5–2秒拆镜。
